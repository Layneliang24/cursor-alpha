# Overview  
Alpha项目英语学习地道表达模块是基于现有英语学习系统的扩展模块，专注于提升英语学习者地道表达能力的沉浸式学习系统。该模块解决了传统英语学习中缺乏地道表达练习、缺少实际使用场景、学习效果难以量化等问题。目标用户是希望提升英语表达地道性的中高级英语学习者。通过智能数据采集、AI助教、场景化学习、数据统计分析等功能，为用户提供个性化、高效的地道表达学习体验。

# Core Features  
## 1. 智能数据采集与管理
- **功能描述**: 基于现有爬虫架构，构建地道表达数据采集系统，包含习语、俚语、口语表达等
- **重要性**: 为整个学习系统提供高质量、实时更新的学习内容基础
- **实现方式**: 
  - 扩展现有news_crawler.py爬虫系统，增加地道表达专用爬虫
  - 集成多数据源：英语学习网站、语言交流论坛、社交媒体
  - 利用现有fundus_crawler框架支持更多英语内容源
  - 支持API接口、文件导入、人工审核的多元化数据获取方式

## 2. 沉浸式场景学习
- **功能描述**: 为每个地道表达提供真实使用场景和对话示例
- **重要性**: 帮助学习者理解表达的实际应用语境，提升学习效果
- **实现方式**: 场景分类管理，多媒体内容支持，互动式场景练习

## 3. AI智能助教系统
- **功能描述**: 通过配置API KEY集成AI模型，提供个性化学习指导和答疑
- **重要性**: 提供24/7智能辅导，根据学习进度调整教学策略
- **实现方式**: 支持多AI模型配置，智能对话接口，学习路径推荐

## 4. 学习数据统计分析
- **功能描述**: 全面记录和分析用户学习行为，生成学习报告和进度追踪
- **重要性**: 量化学习效果，为个性化学习提供数据支撑
- **实现方式**: 多维度数据收集，可视化图表展示，学习洞察生成

## 5. 完善的API接口体系
- **功能描述**: 提供标准化REST API，支持与其他模块和第三方系统集成
- **重要性**: 确保模块的可扩展性和集成能力
- **实现方式**: RESTful API设计，完整的接口文档，版本控制

## 数据模型设计 (基于现有模型扩展)
### 核心数据表扩展
1. **english_expressions** - 扩展现有Expression模型
   - 保留现有字段：expression, meaning, category, scenario, difficulty_level等
   - 新增字段：
     - expression_type (VARCHAR 50) - 类型(idiom/slang/colloquial/phrase)
     - frequency_score (DECIMAL) - 使用频率分数
     - origin_country (VARCHAR 50) - 来源国家/地区
     - formality_level (VARCHAR 20) - 正式程度(formal/informal/neutral)
     - age_group_usage (VARCHAR 50) - 适用年龄群体
     - context_tags (JSON) - 上下文标签
     - pronunciation_guide (TEXT) - 发音指导
     - related_expressions (JSON) - 相关表达ID列表
     - crawl_source (VARCHAR 100) - 爬取来源

2. **english_expression_scenarios** - 使用场景表 (新增)
   - id (Primary Key)
   - expression_id (Foreign Key to english_expressions)
   - scenario_title (VARCHAR 200)
   - scenario_description (TEXT)
   - dialogue_content (JSON) - 对话内容
   - participant_roles (JSON) - 对话角色信息
   - setting_context (VARCHAR 100) - 场景设置
   - media_url (VARCHAR 500) - 多媒体链接
   - created_at, updated_at

3. **english_user_expression_progress** - 学习进度表 (基于现有UserWordProgress)
   - 继承UserWordProgress的SM-2算法相关字段
   - 新增表达特有字段：
     - scenario_familiarity (JSON) - 各场景熟悉度
     - usage_attempts (INT) - 使用尝试次数
     - correct_usage_count (INT) - 正确使用次数
     - last_used_in_context (TEXT) - 最后使用语境
     - ai_feedback_history (JSON) - AI反馈历史

4. **english_expression_sources** - 数据源管理表 (新增)
   - id (Primary Key)
   - source_name (VARCHAR 100) - 数据源名称
   - source_type (VARCHAR 50) - 类型(crawler/api/manual/ai_generated)
   - source_url (VARCHAR 500) - 源URL
   - crawler_class (VARCHAR 100) - 爬虫类名
   - last_crawl_time (DATETIME) - 最后爬取时间
   - crawl_frequency (VARCHAR 20) - 爬取频率
   - data_quality_score (DECIMAL) - 数据质量评分
   - is_active (BOOLEAN) - 是否启用
   - created_at, updated_at

5. **english_ai_assistant_configs** - AI助教配置表 (新增)
   - id (Primary Key)
   - user_id (Foreign Key)
   - ai_provider (VARCHAR 50) - AI提供商(openai/anthropic/custom)
   - api_key_encrypted (TEXT) - 加密的API密钥
   - model_name (VARCHAR 100) - 模型名称
   - personality_settings (JSON) - 个性化设置
   - teaching_style (VARCHAR 50) - 教学风格
   - language_level (VARCHAR 20) - 语言水平设置
   - is_active (BOOLEAN) - 是否启用
   - created_at, updated_at

## API接口规范
### RESTful API设计 (api/v1/english/idiomatic-expressions/)
- GET /expressions/ - 获取表达列表
- POST /expressions/ - 创建新表达
- GET /expressions/{id}/ - 获取表达详情
- PUT /expressions/{id}/ - 更新表达
- DELETE /expressions/{id}/ - 删除表达
- GET /expressions/{id}/scenarios/ - 获取表达场景
- POST /learning/sessions/ - 创建学习会话
- GET /learning/progress/ - 获取学习进度
- POST /ai-assistant/chat/ - AI助教对话
- GET /statistics/dashboard/ - 获取统计数据

# Risks and Mitigations  
## 技术挑战与解决方案
### 风险1: 数据源获取和质量控制
- **挑战描述**: 地道表达数据分散在各种网站和平台，质量参差不齐，存在版权和反爬虫限制
- **解决方案**: 
  - 基于现有爬虫架构，实现多层次数据获取策略
  - 优先使用开放API和合法数据源（如开源词典、学术资源）
  - 实现智能数据质量评估算法，结合人工审核
  - 建立用户贡献和社区验证机制
- **备选方案**: AI生成高质量示例数据，结合少量种子数据进行扩展

### 风险2: 模型变更和系统扩展性
- **挑战描述**: AI模型快速迭代，用户需求变化，系统需要具备强扩展性
- **解决方案**:
  - 采用适配器模式设计AI服务接口，支持热插拔
  - 数据模型设计预留扩展字段(JSON类型)，支持动态属性
  - 基于现有Django架构，利用成熟的ORM和migration系统
  - 实现配置化的功能开关，支持渐进式功能发布
- **技术实现**: 
  ```python
  # AI适配器接口设计
  class BaseAIAdapter:
      def generate_scenario(self, expression: str) -> dict
      def evaluate_usage(self, expression: str, context: str) -> float
      def get_related_expressions(self, expression: str) -> list
  ```

### 风险3: 性能和并发处理
- **挑战描述**: 爬虫任务、AI调用、用户学习数据处理的并发性能要求
- **解决方案**:
  - 利用现有Celery任务队列处理异步爬虫和AI调用
  - 基于现有Redis缓存系统，优化数据访问性能
  - 实现数据库查询优化，建立合适的索引策略
  - 采用分页和懒加载技术，优化前端性能
- **扩展方案**: 预留微服务架构接口，支持未来水平扩展

### 数据源多样化策略
#### 1. 爬虫数据源 (优先级：高)

- **俚语词典**: Urban Dictionary等俚语和口语表达集合

- **开放词典API**: Wordnik, Oxford Dictionary API
- **语言学习API**: Quizlet, Anki等平台的开放接口

#### 3. AI生成数据源 (优先级：中)
- **场景生成**: 使用GPT/Claude生成使用场景和对话
